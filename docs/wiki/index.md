## Decisions
- [[0023-hangar-status-line]]: accepted: `hangar status-line <claude|qwen>` renders two lines (where, how) from the CLI's stdin plus a cached git reading and the account's name and plan, cleaned of control characters and fitted to `COLUMNS`; handed to Claude Code in the same `--settings` as the gate or notice hooks, to Qwen Code in its system settings, to Codex as `-c tui.status_line`, alone when neither applies; protected setting `statusLine`, on by default; a Hangar bar above the terminal for every other agent (sources: 1, updated: 2026-11-27)
- [[0022-models-and-local-llm-servers]]: accepted: model choice per start from the catalog (`models`, `model_args`, `local` for Ollama and LM Studio), probes of both local servers on loopback every 10 s with a status badge in the top bar, a model submenu per program in "New session" with a reasoning effort submenu per model (`efforts`, `effort_args`), Hermes Agent and OpenClaw as new catalog entries (sources: 0, updated: 2026-11-27)
- [[0021-team-decisions]]: accepted: team protocol version 4: decisions with their reasons as shared memory, sealed with the newest notes key (`decision/v1`, bound to team, epoch, notes key id, decision id, sender, log head and counter) and checked against the verified log; `blob.list` (paged, 100, one listing per 5 s), live hints `blob.stored` and `blob.deleted`, at most 200 per team; agents with `context_inject` get them before the reservations, every other session gets "Send to session"; built in the app and both crates, relay specified (sources: 0, updated: 2026-11-25)
- [[0020-proof-of-possession-at-hello]]: accepted: team protocol version 3: `welcome` carries a random challenge from version 3 on, the device answers with `device.prove` (Ed25519 over label, team, holder, key, challenge and version) before its log fetch; in a team with a log a device counts as the log's device only when listed and, on version 3, proven with the log's key, else it may only register, prove itself and read; versions 1 and 2 served under a transition rule; `blob.delete` for author, owner, admin; built in the app and both crates, relay specified (sources: 0, updated: 2026-11-25)
- [[0019-anonymous-usage-statistics]]: accepted: anonymous usage statistics off until the person answers one quiet notice (or the switch in Settings > General > Privacy); consent kept by the backend; counters per UTC day, yesterday's report sent once by the backend (reqwest, official endpoint only, never in debug builds), older days dropped; allowlists in `telemetry_catalog.rs`; no id, path, command or text; built (sources: 0, updated: 2026-11-22)
- [[0018-same-look-on-every-platform]]: accepted: Selawik 1.01 (metric twin of Segoe UI, Latin only) after Segoe UI and Cascadia Mono 2407.24 (variable, own family name) after Consolas in WebKit's stacks only (in Chromium it would take the glyphs the installed fonts lack), bundled as woff2 for macOS and Linux, also as the terminal default there; WebKit only (`data-engine`, `src/webkit.css`) redraws checkbox, radio, slider, select, progress, text, date, time and color fields and the classic scrollbar like WebView2; Linux start test with screenshot in CI (sources: 3, updated: 2026-11-20)
- [[0017-macos-release]]: accepted: macOS arm64 (`macos-latest`) and x64 (`macos-26-intel`) built natively per architecture as `.app.tar.gz` (update format, `darwin-aarch64`, `darwin-x86_64`) plus `.dmg`, macOS 13 minimum, signed ad hoc until an Apple Developer ID exists (then only CI secrets), updater archive signed locally by `release.py --macos`, login shell from `$SHELL`, the account or zsh, own Cmd+Q item that quits through the window; notifications through UNUserNotificationCenter (ad hoc permission unverified), battery from `pmset`, GPU from `ioreg`, CPU and memory from mach and libproc; platform check list; not shipped yet (sources: 5, updated: 2026-11-20)
- [[0016-permission-notices]]: accepted: Claude Code sessions, private ones included, carry report-only http hooks (`PermissionRequest`, `Notification`) with a token of scope `Notify`; a session with a dialog waits with the reason `permission`, so no link message, queued message or agent command presses Enter there; signal cleared by later hook events, the person's answering key, the process end or a 10 minute limit; built; since 0.16.0 the endpoint keeps briefly silent hook connections instead of resetting them (sources: 3, updated: 2026-11-24)
- [[0015-secret-guard]]: accepted: a few precise key and token shapes (PEM private key, AWS, GitHub, Anthropic, OpenAI, Slack, Stripe live) in one module per side with shared vectors; link messages with a secret wait as a card, partner cards say so, the command guard asks before `git add .env` and similar, the commit box asks before committing staged secrets, the paste asks first; only the kind is ever reported; built (sources: 0, updated: 2026-11-20)
- [[0014-session-links]]: accepted: the person links two or more running agent sessions into a link group (color, chain mark; only its composition is remembered and offered again after a restart); members message each other with `hangar-send <name>|all`, delivered automatically with Enter once the target waits, with a loop brake and a per-group "ask before pasting" toggle; optional lead, an in-memory history per group, templates that link, adding sessions to an existing group, merging groups in one backend step, a brake that scales with the members and can be released, `hangar-send --members`, a message stack, messages on their way and a menu on the group label; built (sources: 3, updated: 2026-11-26)
- [[0013-linux-release]]: accepted: Linux x64 as AppImage (the update format, `linux-x86_64`) plus .deb from one target list, built on ubuntu-22.04 for glibc, signed locally with no key in CI, login shell `PATH` at startup, AppImage variables removed for child processes, launcher count through Hangar's own LauncherEntry signal (desktop id from the GLib launcher, AppImageLauncher or `Hangar.desktop`), GPU shown since 2026-11-20; part 1 (bundles in CI) built, release tool signs the CI AppImage under `linux-x86_64-appimage`; desktop notifications on Linux through the freedesktop service (sources: 5, updated: 2026-11-20)
- [[0012-cross-project-messages]]: accepted: messages between sessions of partner projects in different folders; set up once per pair, sent by hand from the session menu or by the agent through `hangar-send` and a token route on the local hook endpoint, pasted as bracketed paste with a header line once the target pauses, an agent's message only after the person's click on its card ("Send" or "Paste only"); parts 1 and 2 built, every line indented since 2026-11-20, delivery measured for six CLIs, `hangar-send` evidenced in the Linux and macOS bundles, Codex sessions get shell environment policy overrides from the user's policy, or no sending when it cannot carry `HANGAR_SEND` (sources: 4, updated: 2026-11-26)
