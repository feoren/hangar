job `macos-bundle` is the first real build.

## Tauri: macOS code signing

URL: https://v2.tauri.app/distribute/sign/macos/

- Ad hoc: "This is useful on ARM (Apple Silicon) devices, where code-signing is required for all
  apps from the Internet." Enabled by "provide the pseudo-identity `-` to Tauri", i.e.
  `"signingIdentity": "-"`.
- "Ad-hoc code signing does not prevent MacOS from requiring users to whitelist the installation
  in their Privacy & Security settings."
- CI variables: `APPLE_CERTIFICATE` (base64 of the exported .p12), `APPLE_CERTIFICATE_PASSWORD`,
  `KEYCHAIN_PASSWORD` (for the guide's own keychain steps), `APPLE_SIGNING_IDENTITY`.
- Notarization, App Store Connect key: `APPLE_API_ISSUER`, `APPLE_API_KEY` (key id),
  `APPLE_API_KEY_PATH` (path of the downloaded private key). Apple ID: `APPLE_ID`,
  `APPLE_PASSWORD` ("an app-specific password"), `APPLE_TEAM_ID`.
- The page does not say which wins when both the config and `APPLE_SIGNING_IDENTITY` name an
  identity.

## Tauri CLI 2.12.4, `crates/tauri-cli/src/interface/rust.rs`

URL: https://raw.githubusercontent.com/tauri-apps/tauri/tauri-cli-v2.12.4/crates/tauri-cli/src/interface/rust.rs

- `let signing_identity = match std::env::var_os("APPLE_SIGNING_IDENTITY") {` with
  `None => config.macos.signing_identity,`: the variable wins over the config.
- `let provider_short_name = match std::env::var_os("APPLE_PROVIDER_SHORT_NAME") {` likewise.
- `hardened_runtime: config.macos.hardened_runtime,` and
  `minimum_system_version: config.macos.minimum_system_version,` have no variable.

## tauri-utils 2.10.2, `MacConfig` (local crate source)

- `minimum_system_version`: "Defaults to `10.13`." and "Setting it to `null` completely removes the
  `LSMinimumSystemVersion` field on the bundle's `Info.plist` and the `MACOSX_DEPLOYMENT_TARGET`
  environment variable."
- `hardened_runtime` defaults to `true` (`default = "default_true"`).
- `platform::bundle_type()`: an unpatched binary counts as `BundleType::App` on macOS
  (`if cfg!(target_os = "macos") { Some(BundleType::App) }`).

## tauri-plugin-updater 2.14.1 (local crate source, `src/updater.rs`)

- `Installer::App`: "macOS application bundle, named `app`. Also used for applications distributed
  as DMG."
- `get_urls`: "we search for [`{os}-{arch}-{installer}`, `{os}-{arch}`] in order"; `updater_os()`
  is `darwin` on macOS, `updater_arch()` `x86_64` or `aarch64`.
- macOS `install_inner`, expected structure: "[AppName]_[version]_x64.app.tar.gz # GZ generated by
  tauri-bundler" holding "[AppName].app". Every entry is extracted with
  `entry.path()?.iter().skip(1)`, so the first path part (the `.app` folder) is dropped and the
  rest goes into a temp folder that replaces the installed bundle (`renamex_np` with
  `RENAME_SWAP`, or two renames; AppleScript "with administrator privileges" when that is denied).

## tao 0.37.2 and tauri-runtime-wry 2.12.3 (local crate source)

- tauri 2.12.5 `Menu::default`: on macOS the application submenu ends with
  `PredefinedMenuItem::quit`; `Builder::enable_macos_default_menu` defaults to `true`.
- muda: `PredefinedMenuItemType::Quit => Some(sel!(terminate:))`.
- tao `app_delegate.rs`: `applicationWillTerminate:` calls `AppState::exit()`, which sends
  `Event::LoopDestroyed`. `RunEvent::ExitRequested` comes only from `Message::RequestExit` (an
  `exit` call) and from the last window being destroyed; a window's `CloseRequested` is not part of
  the `terminate:` path.
- `Event::Reopen { has_visible_windows }` becomes `RunEvent::Reopen` (macOS only): "Emitted when the
  NSApplicationDelegate's applicationShouldHandleReopen gets called".

## Apple

URL: https://developer.apple.com/documentation/macos-release-notes/macos-big-sur-11_0_1-universal-apps-release-notes

- "New in macOS 11 on Macs with Apple silicon, and starting in macOS Big Sur 11 beta 6, the
  operating system enforces that any executable must be signed before it's allowed to run. There
  isn't a specific identity requirement for this signature: a simple ad-hoc signature is
  sufficient."
- "This new policy doesn't apply to translated x86 binaries running under Rosetta 2, nor does it
  apply to macOS 11 running on Intel-based platforms."
- "However, given that these signatures do not bear any valid identity, binaries signed this way
  cannot pass through Gatekeeper."

URL: https://developer.apple.com/news/?id=saqachfa ("Updates to runtime protection in macOS
Sequoia", August 6, 2024)

- "In macOS Sequoia, users will no longer be able to Control-click to override Gatekeeper when
  opening software that isn't signed correctly or notarized. They'll need to visit System Settings
  > Privacy & Security to review security information for software before allowing it to run."

URL: https://support.apple.com/en-us/102445 ("Safely open apps on your Mac")

- Section "If you want to open an app that hasn't been notarized or is from an unidentified
  developer": "Open System Settings." "Click Privacy & Security, scroll down, and click the Open
  Anyway button to confirm your intent to open or install the app." "The warning prompt reappears
  and, if you're absolutely sure that you want to open the app anyway, you can click Open."
- "macOS Catalina and later also requires software to be notarized."

URL: https://support.apple.com/en-us/102360 ("Use zsh as the default shell on Mac")

- "zsh (Z shell) is the default shell for all newly created user accounts, starting with macOS
  10.15."
